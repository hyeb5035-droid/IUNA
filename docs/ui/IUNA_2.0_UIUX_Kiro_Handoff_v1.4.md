# IUNA 2.0 UI/UX 개선 작업 핸드오프
버전: UI/UX v1.4 기준
용도: 기존 Kiro 작업지시 채팅에 업로드하여 기존 작업지시와 병합
작성일: 2026-08-25

---

## 0. 이 파일의 사용 원칙

이 문서는 기존 IUNA 2.0 개발 작업지시를 대체하지 않는다.

기존에 구현된 기능, PRD, DB 구조, Supabase 권한, route, 비즈니스 로직을 유지하면서
UI/UX만 실제 회원 공개 수준으로 정리하기 위한 추가 작업지시다.

우선순위는 다음과 같다.

1. 최신 IUNA 회칙
2. 확정된 최신 PRD
3. 현재 운영 중인 DB/권한 설계
4. 기존 구현 코드
5. 본 UI/UX 작업지시

충돌이 발생하면 임의로 추론해 수정하지 말고 영향 범위를 먼저 보고한다.

특히 이번 작업은:
- 기능 신규 기획 아님
- DB 재설계 아님
- 인증 구조 변경 아님
- route 전면 개편 아님
- 기존 보안 정책 완화 아님

---

# 1. 작업 목적

IUNA 2.0 MVP의 주요 기능 개발은 거의 완료되었다.

이번 작업의 목적은 현재 기능을 유지하면서 약 200명의 실제 회원에게 공개할 수 있는 수준으로
서비스 전체 UI/UX를 정리하는 것이다.

현재 주요 문제:

- 개발용 프로토타입처럼 보임
- 카드가 지나치게 크고 반복적임
- 정보 위계가 약함
- 공통 navigation이 없음
- Home / Meetings / My / Admin 이동 체계가 일관되지 않음
- 운영진 기능과 일반 회원 기능의 시각적 위계가 불명확함
- 일부 화면에서 뒤로가기 링크가 페이지별로 임의 구현됨
- 모바일에서 정보 밀도가 낮음

---

# 2. 디자인 방향

IUNA는 다양한 직업과 경험을 가진 사람들이 함께 배우고 성장하는 커뮤니티다.

목표 키워드:

- Warm
- Clean
- Modern
- Trustworthy
- Community
- Growth

피해야 할 방향:

- 관리자 SaaS처럼 딱딱한 UI
- 모든 정보를 큰 카드로 감싸는 UI
- 강한 그림자
- 과도한 컬러
- 감성적인 동호회 스타일
- 불필요한 장식
- route/기능 변경을 수반하는 과도한 재설계

기본 방향:

- 모바일 우선 반응형 웹
- 따뜻한 off-white 배경
- white surface
- black primary
- neutral gray
- 상태 색상은 의미가 있을 때만 사용

# 3. 현재 유지해야 할 route

회원:

- /home
- /my
- /my/edit
- /meetings
- /meetings/new
- /meetings/[id]
- /meetings/[id]/applicants
- /meetings/[id]/attendance

운영:

- /admin
- /admin/members
- /admin/meetings

기존 route를 삭제/변경하기 전에 반드시 영향 범위를 확인한다.

특히 `/admin/meetings`는 현재 어떤 기능을 담당하는지 먼저 분석하고,
UI상 별도 "모임 관리" navigation은 제거하되 기존 기능을 잃지 않도록 한다.

---

# 4. 공통 Navigation

## 일반 회원

모바일 하단 탭:

- 홈
- 모임
- 마이

경로:

- 홈 → /home
- 모임 → /meetings
- 마이 → /my

일반 회원에게는 "관리" 탭을 노출하지 않는다.

로그아웃은 핵심 navigation이 아니며 마이페이지의 보조 기능으로 둔다.

## 운영진

운영진에게만 하단 탭에 "관리"를 추가한다.

- 홈
- 모임
- 마이
- 관리

관리 탭 → /admin

운영진 여부는 UI 표시뿐 아니라 실제 backend authorization과 일치해야 한다.

# 6. 운영진 역할별 권한

운영진 권한은 다음 4개다.

## 6.1 일반 운영진

권한:
- 회원 정보 전체 조회

관리 메뉴:
- 회원 조회

불가:
- 회원 등급 변경
- 모임 승인
- 운영진 역할 변경

---

## 6.2 회원 관리 운영진

권한:
- 회원 정보 전체 조회
- 회원 등급 변경

관리 메뉴:
- 회원 조회

회원 화면에서:
- 준회원 포인트 표시
- 5점 이상 준회원만 정회원 승급 action 활성화
- 5점 미만은 승급 불가

---

## 6.3 모임 관리 운영진

권한:
- 회원 정보 전체 조회
- 모임 승인

관리 메뉴:
- 회원 조회
- 모임 승인

중요:
- 별도의 "모임 관리" 메뉴를 두지 않는다.
- navigation에는 "모임 승인"만 존재한다.

---

## 6.4 슈퍼 운영진

권한:
- 회원 정보 전체 조회
- 회원 등급 변경
- 모임 승인
- 운영진 역할 부여/변경

관리 메뉴:
- 회원 관리
- 모임 승인

중요:
- 별도의 "운영진 역할 관리" 페이지/메뉴를 두지 않는다.
- 운영진 역할 지정/변경은 회원 관리 페이지 내부 action으로 처리한다.
- 별도의 "모임 관리" 메뉴도 두지 않는다.

# 16. 회원 관리 — 단일 허브 페이지

모든 운영진이 동일한 회원 관리 페이지에 접근한다.

이 한 페이지에서 다음 기능을 통합한다.

- 회원 조회
- 정회원 승급
- 운영진 지정/역할 변경

별도의:
- 회원 승급 페이지
- 운영진 지정 페이지
- 운영진 역할 관리 페이지

를 만들지 않는다.

검색:
- 회원번호
- 이름

필터:
- 전체
- 준회원
- 정회원
- 명예회원
- 활동
- 휴면
- 탈퇴
- 제명

목록 주요 정보:
- 회원번호
- 이름
- 등급
- 상태
- 가입일
- 포인트
- 관리 action

## 권한별 action

### 일반 운영진
- 상세 조회만 가능

### 회원 관리 운영진
- 상세 조회
- 준회원 정회원 승급

### 모임 관리 운영진
- 상세 조회만 가능

### 슈퍼 운영진
- 상세 조회
- 준회원 정회원 승급
- 정회원/적격 회원 운영진 지정 및 역할 변경

## 대상 회원별 action

### 준회원
포인트 표시.

5점 이상 + 회원 등급 변경 권한 보유:
- 승급 대상 badge
- 정회원 승급 버튼 활성화

5점 미만:
- 정회원 승급 버튼 비활성 또는 미노출
- backend에서도 승급 불가

### 정회원
슈퍼 운영진에게만:
- 운영진 지정 버튼 표시

일반 운영진/회원 관리 운영진/모임 관리 운영진:
- 운영진 지정 action 미노출

### 운영진
슈퍼 운영진에게만:
- 현재 운영진 역할 확인
- 역할 변경 action 제공

중요:
UI의 버튼 노출만 바꾸는 것이 아니라 실제 backend authorization과 동일해야 한다.

# 19. 운영진 지정/역할 변경

별도 페이지를 만들지 않는다.

슈퍼 운영진은 `회원 관리` 페이지에서 대상 회원 row의 action을 통해 운영진 역할을 지정하거나 변경한다.

가능한 역할:

- 일반 운영진
- 회원 관리 운영진
- 모임 관리 운영진
- 슈퍼 운영진

UI 예:

정회원 row:
- 상세
- 운영진 지정

기존 운영진 row:
- 상세
- 운영진 역할 변경

action 클릭 시 modal / inline panel / bottom sheet 등 현재 구현 난이도가 가장 낮은 패턴을 사용한다.

실제 DB role 구조는 현재 schema를 확인 후 재사용한다.
UI 요구사항 때문에 role schema를 임의 변경하지 않는다.

# 26. 권한 보안

UI 숨김은 보안이 아니다.

다음 기능은 실제 backend 권한과 반드시 일치해야 한다.

- 회원 전체 조회
- 회원 등급 변경
- 모임 승인/반려
- 운영진 역할 변경

현재 Supabase RLS / RPC / server action 정책 먼저 확인.

이번 UI 작업 중 기존 보안 정책을 약화하지 않는다.

직접 URL 접근/API 호출로 권한을 우회할 수 없어야 한다.

# 31. UI/UX v1.4 최종 추가 결정

회원 관련 운영 기능은 하나의 페이지로 통합한다.

`회원 관리` 페이지가 다음 세 기능의 단일 진입점이다.

1. 회원 조회
2. 정회원 승급
3. 운영진 지정/역할 변경

별도 페이지를 생성하지 않는다.

버튼 활성/노출 기준은:
- 로그인 운영진의 권한
- 대상 회원의 현재 등급/상태
- 준회원의 경우 승급 포인트 충족 여부

에 따라 결정한다.

이 결정은 기존 `/admin/members` route를 최대한 재사용하는 방향으로 구현한다.
